================================================================================
HOWDY-BACKEND — GitHub + Cloud Run configuration checklist
================================================================================
Use the GitHub Actions environment named in .github/workflows/deploy.yml (e.g.
"dev"): Settings → Environments → [environment] → Environment secrets / Variables.

Secrets are masked in logs. Variables are for non-sensitive config (URLs, flags).

Do not commit real keys. Replace placeholders with your values.

================================================================================
1) GITHUB ACTIONS — required for CI (build, push, deploy)
================================================================================
These are read as secrets.* in deploy.yml.

  GCP_SA_KEY
    JSON key for a service account used ONLY in CI.
    Needs: Artifact Registry push, Cloud Run deploy, (often) enable APIs.
    Create in GCP IAM; store entire JSON as one secret.

  GCP_PROJECT_ID
    GCP project id (e.g. howdy-app-123). Must match the project where Artifact
    Registry and Cloud Run live.

  GCP_RUN_REGION
    Region for BOTH:
      - Artifact Registry hostname: {REGION}-docker.pkg.dev
      - Cloud Run deploy: gcloud run deploy --region
    Use a single region name only, e.g. europe-west2 or us-central1
    (no "-docker.pkg.dev" suffix).

  GCP_ARTIFACT_REPOSITORY  (optional)
    Name of the Docker repository INSIDE Artifact Registry.
    If unset, workflow defaults to: howdy
    Must exist in GCP at GCP_RUN_REGION (create if you see "Repository not found").

  GCP_RUN_SERVICE  (optional)
    Cloud Run service name. If unset, workflow defaults to: howdy-backend

================================================================================
2) GITHUB — Variables (not secrets) for public URLs
================================================================================
Configure under the same environment: Variables (vars.*).

These replace what dev.sh/ngrok set locally (PUBLIC_BASE_URL, API_BASE_URL, etc.).

  PUBLIC_BASE_URL
    HTTPS origin of this API on the internet, e.g.
 https://howdy-backend-xxxxx-REGION.run.app
    or your custom domain. Used for webhooks and absolute URLs.

  API_BASE_URL
    Often the same as PUBLIC_BASE_URL if the app calls this service directly.
    Backend code uses this when building some links.

  INVITE_LANDING_BASE_URL
    Base URL for invite/landing flows. Often same as PUBLIC_BASE_URL unless
    landing is on another host.

If a Variable is empty, it is omitted from Cloud Run env (workflow skips empty).

================================================================================
3) GITHUB — Secrets passed through to Cloud Run at deploy time
================================================================================
The deploy step only forwards non-empty values. Set each you need for production.

--- Core / auth / Firebase ---
  JWT_SECRET
    Required for HS256 JWT verification (auth).

  FIREBASE_BUCKET
    GCS bucket name passed to Firebase Admin (storageBucket), e.g. your-project.appspot.com

  PII_ENCRYPTION_KEY
    Base64-encoded 32-byte key for AES-256-GCM PII fields (optional locally warns).

--- Stripe ---
  STRIPE_SECRET_KEY
  STRIPE_WEBHOOK_SECRET

--- Agora (calls / recording) ---
  AGORA_APP_ID
  AGORA_APP_CERTIFICATE
  AGORA_REC_CUSTOMER_ID
  AGORA_REC_CUSTOMER_CERT
  AGORA_REC_REGION
    Example region value: NA

--- GCS (recordings / transcripts paths) ---
  GCS_BUCKET
  GCS_PREFIX
  GCS_INTEROP_ACCESS_KEY
  GCS_INTEROP_SECRET_KEY
  TRANSCRIPTS_PREFIX
  ARCHIVE_TRANSCRIPTS_TO_GCS
    Typical: true or false

--- Transcription (AssemblyAI and/or Cloudflare) ---
  ASSEMBLYAI_API_KEY
  ASSEMBLYAI_WEBHOOK_SECRET

--- Other product secrets ---
  REVENUECAT_KEY
    (Optional; limited use in current server code.)

  OPENAI_API_KEY

--- Email ---
  SMTP_HOST
  SMTP_PORT
  SMTP_USER
  SMTP_PASS

--- Yoti (IDV) — Cloud Run uses PEM via base64, not a file path ---
  YOTI_ENV
    e.g. sandbox or production

  YOTI_CLIENT_SDK_ID

  YOTI_KEY_PEM_B64
    REQUIRED for Cloud Run: base64 of the PEM file, single line, no newlines.
    Example (macOS/Linux):
      base64 -i privateKey.pem | tr -d '\n'
    Local dev can use YOTI_KEY_FILE instead (not used by current workflow).

  YOTI_SUCCESS_URL
    e.g. howdy://verify-success

  YOTI_ERROR_URL
    e.g. howdy://verify-failure

  YOTI_WEBHOOK_AUTH
    Optional; default in code is howdy:yoti

--- Cron / misc ---
  ENABLE_TRANSCRIPT_BACKFILL
    Optional; default in code is true if unset

================================================================================
4) Local dev.sh / env.local.sh → what to set in GitHub / Cloud Run
================================================================================
dev.sh sets these dynamically; in production you set stable values yourself.

  dev.sh / ngrok          →  PUBLIC_BASE_URL (Variable) = real HTTPS API URL
  LAN API_BASE_URL        →  API_BASE_URL (Variable) = same public URL usually
  INVITE_LANDING_*        →  INVITE_LANDING_BASE_URL (Variable)
  YOTI_WEBHOOK_URL        →  Derived from PUBLIC_BASE_URL + /yoti/webhook if unset,
 or set explicitly in GCP later if you extend workflow
  GOOGLE_APPLICATION_CREDENTIALS (local file)
 →  Not set in Cloud Run; use Cloud Run service account with Firestore/Storage roles
  USE_NGROK*, HOST_IP, PORT for devices
                          →  Not applicable on Cloud Run
  DEMO_YOTI_* (Flutter)   →  Client dart-define; not server env for this backend

================================================================================
6) After first successful deploy
================================================================================
  - Copy the Cloud Run service URL from GCP console and set PUBLIC_BASE_URL /
 API_BASE_URL / INVITE_LANDING_BASE_URL if you used placeholders.
  - Point Stripe / AssemblyAI / Yoti webhooks at your public URLs.
  - Ensure Cloud Run service account has roles: Firestore, Storage, any GCP APIs you use.
